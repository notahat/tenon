# `tenon-generate`

CLI that introspects a Postgres database and writes a typed
schema file.

```sh
npx tenon-generate \
  --database-url postgres://localhost/myapp_dev \
  [--schemas public[,other...]] \
  --output src/schema.ts
```

The CLI is exposed via the `bin` field of `@notahat/tenon`, so
`npx tenon-generate ...` works once the package is installed.

## Flags

### `--database-url <url>` (required)

Any Postgres connection string `pg` understands. The CLI reads
the catalog through this connection; it does not write.

### `--schemas <list>` (optional)

Comma-separated list of schema names to introspect. Defaults to
`public`. Whitespace around commas is trimmed; empty entries are
rejected.

### `--output <path>` (required)

Path to write the generated TypeScript module. Overwritten on
every run; the file's first line says so.

## Output format

The CLI emits one `defineTable(...)` call per table, in catalog
order. A small header comment, then one import:

```ts
// This file is generated by tenon-generate. Do not edit by hand.
// Re-run `tenon-generate` after schema migrations.

import { columnType, defineTable } from "@notahat/tenon/schema-runtime";

export const users = defineTable("public", "users", {
  id: columnType<number, "int4">({
    nullable: false,
    hasDefault: true,
    isGenerated: false,
  }),
  email: columnType<string, "text">({
    nullable: false,
    hasDefault: false,
    isGenerated: false,
  }),
  // ...
});
```

The export name is derived from the table name. Non-identifier
characters are replaced with underscores; a leading digit is
prefixed with `_`.

## Type mapping

The default Postgres-to-TypeScript map is in the
[type mapping guide](../guide/type-mapping.md). Unknown types
fall back to `string` and the generated file carries a comment
naming the offending type:

```ts
status: columnType<string, "subscription_status">({
  nullable: false,
  hasDefault: false,
  isGenerated: false,
}), // unknown Postgres type "subscription_status"; falling back to string
```

## Exit codes

- `0` — success.
- `2` — bad arguments (missing required flag, missing value for a
  flag). The CLI writes the usage line to stderr.

Errors from `pg` (connection refused, authentication failure,
missing schema) propagate as uncaught exceptions and the process
exits non-zero with a stack trace.

## What's not exposed

- Inclusion / exclusion filters beyond the schema list. Adding a
  table-name filter requires a second consumer with a real need.
- A configuration file. Environment variables and flags are the
  full surface.
- Type-map overrides. If you need a custom mapping for a
  particular column, edit the generated file (and accept that
  it'll be lost on regeneration), or open an issue.
