# `tenon` — basic UPDATE (v1.13)

## Context

`tenon` v1.12 added `find(id).delete()` on top of v1.8's predicate-narrowed
DELETE. The library can now read, insert, and remove rows; it cannot yet
modify them. UPDATE is the last write operator before the v1 surface is
complete.

This iteration adds **basic UPDATE** with an optional `RETURNING` clause,
accessed through the same surfaces DELETE uses:

```ts
// Predicate-narrowed UPDATE.
await db.run(users.where(users.id.eq(42)).update({ name: "Pete" }));
// -> { rowCount: number }

// Multiple predicates AND together (chain stays in scope).
await db.run(
  users
    .where(users.email.eq("pete@notahat.com"))
    .where(users.active.eq(true))
    .update({ name: "Pete" }),
);

// RETURNING produces typed rows, same shape as Insert/Delete.
const updated = await db.run(
  users
    .where(users.id.eq(42))
    .update({ name: "Pete" })
    .returning(users.id, users.email),
);
//    ^? Array<{ id: number; email: string }>

// Primary-key shorthand via find().
await db.run(users.find(42).update({ name: "Pete" }));
// -> { rowCount: 0 | 1 }
```

User-confirmed scope decisions:

- **Surface:** `Table.where(...).update(attrs)` and
  `Table.find(id).update(attrs)`. **No** `Table.updateAll(...)`, **no**
  `Table.update(...)` footgun catch — `update` is gated by where/find.
- **Class shape:** the existing `DeletableScope` and
  `DeletableSingleRow` both gain `.update(...)` and are renamed to
  `WritableScope` and `WritableSingleRow`. One scope = both `.delete`
  and `.update`.
- **Updatable attrs:** all non-generated columns, all optional, with
  `null` accepted only for nullable columns. PK is updatable.
- **RHS values:** literals only (parameters), like `.insert(...)`.
- **RETURNING:** same shape as Insert/Delete via `.returning(...)`.
- **Empty attrs (`update({})`):** runtime throw in the serialiser
  (defensive — TS allows it).
- **Empty WHERE:** runtime throw in the serialiser (defensive — every
  construction site supplies predicates).
- **No `UPDATE ... FROM`** (multi-table update). Deferred, matches the
  posture taken with `DELETE ... USING`.

## Decisions

- **`Update` is its own AST + class, not a `RelationNode` variant.**
  Same reasoning as `Insert` and `Delete`: keeps the SELECT serialiser,
  duplicate-column brand, and join machinery free of statement-category
  guards.
- **`UpdateNode` carries assignments as a flat
  `readonly UpdateAssignment[]`.** Each entry is a `{ column, value }`
  pair, where `value` is an `ExpressionNode` (currently always a
  `Parameter`). Mirrors `InsertColumnValue`. Order is preserved from
  the user's object key order so SQL output is deterministic.
- **`UpdateNode.predicates` is a flat `ExpressionNode[]`,** built once
  by walking the `WritableScope`'s relation node back through its
  `Where` ancestors. Same `collectWherePredicates` helper that
  `WritableScope.delete` uses today.
- **No `allowEmptyPredicates` flag on `UpdateNode`.** Without an
  `updateAll()` escape hatch there is no construction site that
  legitimately produces an empty predicate list, so the serialiser
  unconditionally throws on empty WHERE. Aligns with the "no surface
  exists" decision; leaves the AST simpler than `DeleteNode`.
- **Empty-assignments guard lives in the serialiser too.** Type
  machinery doesn't catch `update({})` (every key is optional), so the
  guard is the only defence. Throws with a clear message naming the
  call site.
- **`WritableScope.update(attrs)` builds an `UpdateAssignment[]` from
  `Object.entries(attrs)` in the same fashion `Table.insert` builds its
  `InsertColumnValue[]`.** Each value goes through `parameter(value)`
  to produce the `ExpressionNode`. Iteration order preserves the user's
  object-key order.
- **Alias is preserved on emit** (matching DELETE, contra INSERT).
  Predicates qualify columns by the table's alias, so dropping it
  would break aliased updates. Reuse the existing `emitTableRef`.
- **`Update<Columns, Returning>` mirrors `Insert<Columns, Returning>`
  and `Delete<Columns, Returning>`** — same phantom generics, same
  `.returning(...)` shape, same `Database.run` overload pair (with-
  Returning → typed rows; without → `{ rowCount }`).
- **Renames are mechanical, not behavioural.** `DeletableScope` →
  `WritableScope`, `DeletableSingleRow` → `WritableSingleRow`. Both
  classes already extend Relation / SingleRow; the new name better
  describes the shared role once `.update` lands. Files are renamed
  with the classes; export sites in `src/index.ts` change accordingly.

## Design

### AST

New file `src/ast/update.ts`:

```ts
import type { ExpressionNode } from "./expression.js";
import type { ProjectionItem, TableRef } from "./relation.js";

/** A single (column, value) SET assignment for an UPDATE. */
export interface UpdateAssignment {
  readonly column: string;
  readonly value: ExpressionNode;
}

/**
 * An UPDATE statement targeting a single base table. Assignments are
 * emitted in array order (matching the user's object-key order). The
 * predicate list is AND-ed at emit time. The serialiser throws on an
 * empty assignment list or an empty predicate list — neither is
 * reachable from the public surface, but the guards make the error
 * loud rather than letting Postgres reject mangled SQL.
 */
export interface UpdateNode {
  readonly kind: "Update";
  readonly target: TableRef;
  readonly assignments: readonly UpdateAssignment[];
  readonly predicates: readonly ExpressionNode[];
  readonly returning: readonly ProjectionItem[] | null;
}

export function updateAssignment(
  column: string,
  value: ExpressionNode,
): UpdateAssignment {
  return { column, value };
}

export function updateNode(args: {
  readonly target: TableRef;
  readonly assignments: readonly UpdateAssignment[];
  readonly predicates: readonly ExpressionNode[];
  readonly returning?: readonly ProjectionItem[] | null;
}): UpdateNode {
  return {
    kind: "Update",
    target: args.target,
    assignments: args.assignments,
    predicates: args.predicates,
    returning: args.returning ?? null,
  };
}
```

`UpdateNode` is **not** a member of `RelationNode`. `relationToSql`'s
exhaustive switch is unaffected.

### Serialiser

`src/sql/serialise.ts` — add `updateToSql` next to `deleteToSql`,
sharing the same `EmitContext`, `emitTableRef`, `emitExpression`,
`emitPredicates`, and `emitSelectList`.

```ts
export function updateToSql(node: UpdateNode): CompiledQuery {
  const context: EmitContext = { params: [] };
  const text = emitUpdate(node, context);
  return { text, params: context.params };
}

function emitUpdate(node: UpdateNode, context: EmitContext): string {
  if (node.assignments.length === 0) {
    throw new Error(
      "UPDATE without any SET assignments is forbidden. " +
        "Pass at least one column to update(...).",
    );
  }
  if (node.predicates.length === 0) {
    throw new Error(
      "UPDATE without a WHERE clause is forbidden. " +
        "Narrow the target with .where(...) or .find(id).",
    );
  }
  const target = emitTableRef(node.target);
  const assignments = node.assignments
    .map((assignment) => emitAssignment(assignment, context))
    .join(", ");
  const where = `WHERE ${emitPredicates(node.predicates, context)}`;
  const returning =
    node.returning === null
      ? ""
      : ` RETURNING ${emitSelectList(node.returning, context)}`;
  return `UPDATE ${target} SET ${assignments} ${where}${returning}`;
}

function emitAssignment(
  assignment: UpdateAssignment,
  context: EmitContext,
): string {
  return `${quoteIdent(assignment.column)} = ${emitExpression(assignment.value, context)}`;
}
```

Parameter numbering: SET first (left-to-right across assignments), then
WHERE, then RETURNING — same canonical "writes-then-reads" order Insert
and Delete already use.

### Fluent layer

New file `src/query/Update.ts`:

```ts
import { updateNode, type UpdateNode } from "../ast/update.js";
import type { ColumnsShape } from "../schema-runtime/columnType.js";
import { toProjectionItem } from "./projection.js";
import type { ProjectableItem, ProjectedShape } from "./types.js";

export class Update<
  Columns extends ColumnsShape,
  Returning extends ColumnsShape | null,
> {
  declare readonly _columns: Columns;
  declare readonly _returning: Returning;

  constructor(readonly node: UpdateNode) {}

  /** Add or replace the RETURNING clause. */
  returning<const Items extends readonly ProjectableItem[]>(
    ...items: Items
  ): Update<Columns, ProjectedShape<Items>> {
    const projectionItems = items.map(toProjectionItem);
    return new Update<Columns, ProjectedShape<Items>>(
      updateNode({
        target: this.node.target,
        assignments: this.node.assignments,
        predicates: this.node.predicates,
        returning: projectionItems,
      }),
    );
  }
}
```

Renamed file `src/query/WritableScope.ts` (was `DeletableScope.ts`):

```ts
export class WritableScope<
  TableName extends string,
  Columns extends ColumnsShape,
  FKs extends ForeignKeyTuple = readonly [],
> extends Relation<Columns, FKs> {
  declare readonly _tableName: TableName;

  constructor(
    node: RelationNode,
    private readonly target: TableRef,
  ) {
    super(node);
  }

  override where(
    predicate: Expression<boolean>,
  ): WritableScope<TableName, Columns, FKs> {
    return new WritableScope<TableName, Columns, FKs>(
      whereNode(this.node, predicate.node),
      this.target,
    );
  }

  /** Build a DELETE from the accumulated predicates. */
  delete(): Delete<Columns, null> {
    const predicates = collectWherePredicates(this.node);
    return new Delete<Columns, null>(
      deleteNode({
        target: this.target,
        predicates,
        allowEmptyPredicates: false,
      }),
    );
  }

  /**
   * Build an UPDATE setting the given columns. Attrs are interpreted
   * as a literal-valued SET list; column-key order is preserved.
   * Without `.returning(...)` the run resolves to `{ rowCount }`.
   */
  update(attrs: UpdatableAttrs<Columns>): Update<Columns, null> {
    const predicates = collectWherePredicates(this.node);
    const assignments = Object.entries(
      attrs as Record<string, unknown>,
    ).map(([columnName, value]) =>
      updateAssignment(columnName, parameter(value)),
    );
    return new Update<Columns, null>(
      updateNode({
        target: this.target,
        assignments,
        predicates,
      }),
    );
  }
}
```

`collectWherePredicates` stays in this file.

Renamed file `src/query/SingleRow.ts` keeps `SingleRow`,
`SingleRowOrThrow`, `RowNotFoundError`, but renames
`DeletableSingleRow` → `WritableSingleRow` and adds an `.update(attrs)`

```ts
export class WritableSingleRow<
  Columns extends ColumnsShape,
> extends SingleRow<Columns> {
  constructor(
    node: RelationNode,
    private readonly target: TableRef,
    private readonly predicates: readonly ExpressionNode[],
  ) {
    super(node);
  }

  delete(): Delete<Columns, null> { /* unchanged */ }

  update(attrs: UpdatableAttrs<Columns>): Update<Columns, null> {
    const assignments = Object.entries(
      attrs as Record<string, unknown>,
    ).map(([columnName, value]) =>
      updateAssignment(columnName, parameter(value)),
    );
    return new Update<Columns, null>(
      updateNode({
        target: this.target,
        assignments,
        predicates: this.predicates,
      }),
    );
  }
}
```

### Type machinery

`src/query/types.ts` — add `UpdatableAttrs<Columns>`:

```ts
/**
 * The TS shape `.update(attrs)` accepts. All non-generated columns are
 * optional. Nullable columns also accept `null`; non-nullable columns
 * do not. PK is updatable. `hasDefault` is irrelevant for UPDATE
 * (defaults only apply on INSERT) so it is not consulted.
 */
export type UpdatableAttrs<Columns extends ColumnsShape> = Prettify<{
  [Name in keyof Columns as Columns[Name]["isGenerated"] extends true
    ? never
    : Name]?: Columns[Name]["nullable"] extends true
    ? Columns[Name]["_tsType"] | null
    : Columns[Name]["_tsType"];
}>;
```

`Prettify` already exists locally in `types.ts`; reuse.

### `Database.run` overloads

`src/executor/Database.ts` — add Update overloads alongside Delete and
Insert. Order doesn't matter between classes (each is discriminated by
the wrapper type); within the class the with-Returning overload comes
first.

```ts
run<Columns extends ColumnsShape, Returning extends ColumnsShape>(
  statement: Update<Columns, Returning>,
  client?: PoolClient,
): Promise<RowOf<Returning>[]>;
run<Columns extends ColumnsShape>(
  statement: Update<Columns, null>,
  client?: PoolClient,
): Promise<{ readonly rowCount: number }>;
```

Implementation: extend the `instanceof` cascade with an `Update` branch
that calls `updateToSql` and applies the same RETURNING/rowCount split
already used for Insert and Delete.
