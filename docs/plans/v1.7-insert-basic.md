# `tenon` — basic INSERT (v1.7)

## Context

`tenon` v1.6 shipped joins + table aliasing. The library is still
SELECT-only: `Database.run` accepts a `Relation`, the SQL serialiser
emits a `SELECT`, and there is no AST node, fluent surface, or type
machinery for write statements (verified — `INSERT` appears only inside
test fixture SQL).

The next increment is **basic single-row INSERT** with an optional
`RETURNING` clause:

```ts
// no RETURNING -> resolves to { rowCount }
await db.run(users.insert({ email: "pete@notahat.com", name: "Pete" }));

// with RETURNING -> resolves to typed rows
const created = await db.run(
  users
    .insert({ email: "pete@notahat.com", name: "Pete" })
    .returning(users.id, users.created_at),
);
// created: { id: number; created_at: Date }[]
```

For the inferred-attrs typing to be ergonomic (omit serial PKs and
`DEFAULT`-bearing columns), the schema runtime needs to know which
columns have defaults and which are computed. Today `ColumnType` only
tracks `nullable`. So this iteration also extends:

- `ColumnType` with two sibling flags `hasDefault` and `isGenerated`,
- the introspector to read `pg_attribute.atthasdef` /
  `attidentity` / `attgenerated`,
- generated schema files to emit the new flags.

The Rails-style `users.where(condition).insert(attrs)` chain is
**explicitly out of scope** for this iteration (deferred to v1.8).

## Decisions

- **Single-row inserts only.** `insertMany` is deferred; the AST is
  shaped to admit it later (column-values list rather than a single
  values map) but the fluent surface only takes one row.
- **`Insert` is its own AST + class, not a `RelationNode` variant.**
  An INSERT is a different statement category from a SELECT; mixing
  them under `RelationNode` would force the SELECT serialiser, the
  duplicate-column brand, and the join machinery to all carry "is
  this a relation?" guards.
- **`.insert` lives on `Table`, not `Relation`.** Only base tables
  can be the target of an INSERT. `users.where(...).insert(...)`
  does not typecheck; users get a clear "no such method" error.
  After `.as("u")`, the insert still works (the alias is dropped on
  emit — Postgres allows aliased INSERT but it's pointless).
- **Throw at runtime** (in the serialiser) if an INSERT carries an
  empty column-values list and the table has any required columns —
  Postgres would surface a clearer error, but we want to fail before
  the round-trip.
- **Schema runtime: flat siblings, not a flags bag.** Add
  `hasDefault` and `isGenerated` alongside `nullable` on
  `ColumnType` rather than nesting them under a `flags` object. Five
  generic params is verbose, but the factory hides them and the
  read sites (`RowOf`, `InsertableAttrs`) stay flat. Matches the
  existing `nullable` pattern; cheap upgrade for hand-written
  schemas.
- **Generated columns are forbidden in inserts at the type level.**
  `InsertableAttrs<Columns>` simply omits keys whose `isGenerated`
  is `true`. Trying to set one is a "no such property" error; the
  serialiser additionally throws if it's somehow passed at runtime.
- **No ON CONFLICT, no UPDATE, no DELETE.** Each is a separate
  iteration; nothing about this design forecloses them.

## Design

### Schema runtime extension

`src/schema-runtime/columnType.ts`:

```ts
export interface ColumnType<
  TsType,
  SqlTag extends string,
  Nullable extends boolean,
  HasDefault extends boolean,
  IsGenerated extends boolean,
> {
  readonly _tsType: TsType;
  readonly _sqlTag: SqlTag;
  readonly nullable: Nullable;
  /**
   * True if the column has a DEFAULT clause or is an identity
   * column (serial / GENERATED ... AS IDENTITY). Optional in
   * inserts.
   */
  readonly hasDefault: HasDefault;
  /**
   * True if the column is GENERATED ALWAYS AS (expr) STORED.
   * Forbidden in inserts.
   */
  readonly isGenerated: IsGenerated;
}

export type ColumnsShape = Readonly<
  Record<string, ColumnType<unknown, string, boolean, boolean, boolean>>
>;
```

Factory: `columnType<TsType, SqlTag>({ nullable, hasDefault, isGenerated })`.
Existing literal-overloads on `nullable` are kept so it stays narrow
in the result type.

`RowOf<Columns>` is unchanged — it only reads `nullable` and `_tsType`.

### Introspector extension

`src/introspect/readCatalog.ts` — extend the SQL:

```sql
SELECT
  n.nspname AS schema,
  c.relname AS table_name,
  a.attname AS column_name,
  t.typname AS typname,
  NOT a.attnotnull AS nullable,
  (a.atthasdef OR a.attidentity <> '')   AS has_default,
  (a.attgenerated <> '')                 AS is_generated
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
JOIN pg_attribute a ON a.attrelid = c.oid
JOIN pg_type      t ON t.oid = a.atttypid
WHERE n.nspname = ANY($1::text[])
  AND c.relkind IN ('r','v','m','p')
  AND a.attnum  > 0
  AND NOT a.attisdropped
ORDER BY n.nspname, c.relname, a.attnum
```

`CatalogColumn` gains `hasDefault: boolean` and `isGenerated: boolean`.
`groupByTable` is unchanged.

`src/introspect/emit.ts` — `renderColumnLine` extends to:

```ts
`{ nullable: ${column.nullable}, hasDefault: ${column.hasDefault}, isGenerated: ${column.isGenerated} }`;
```

### Insert AST

New file `src/ast/insert.ts`:

```ts
import type { ExpressionNode } from "./expression.js";
import type { ProjectionItem, TableRef } from "./relation.js";

/** A single (column, value) pair for an INSERT row. */
export interface InsertColumnValue {
  readonly column: string; // physical column name
  readonly value: ExpressionNode; // currently always a Parameter
}

/**
 * An INSERT statement targeting a single base table. The column-
 * values list is left in user-supplied order; serialisation
 * preserves that order for both column list and VALUES list.
 */
export interface InsertNode {
  readonly kind: "Insert";
  readonly target: TableRef; // alias is ignored on emit
  readonly columnValues: readonly InsertColumnValue[];
  readonly returning: readonly ProjectionItem[] | null;
}

export function insertNode(args: {
  readonly target: TableRef;
  readonly columnValues: readonly InsertColumnValue[];
  readonly returning?: readonly ProjectionItem[] | null;
}): InsertNode {
  return {
    kind: "Insert",
    target: args.target,
    columnValues: args.columnValues,
    returning: args.returning ?? null,
  };
}

export function insertColumnValue(
  column: string,
  value: ExpressionNode,
): InsertColumnValue {
  return { column, value };
}
```

`InsertNode` is **not** a member of `RelationNode`. `relationToSql`
keeps its existing exhaustive switch.

### Serialiser

`src/sql/serialise.ts` — add a sibling top-level entry point. The
`EmitContext` and `emitExpression` helpers stay module-private; we
just add `insertToSql` next to `relationToSql` so both share them.

```ts
export function insertToSql(node: InsertNode): CompiledQuery {
  const ctx: EmitContext = { params: [] };
  const text = emitInsert(node, ctx);
  return { text, params: ctx.params };
}

function emitInsert(node: InsertNode, ctx: EmitContext): string {
  // INSERT INTO "schema"."name" (cols) VALUES (params) [RETURNING ...]
  const target = `${quoteIdent(node.target.schema)}.${quoteIdent(node.target.name)}`;
  if (node.columnValues.length === 0) {
    // Rare in practice — only valid when every column has a default.
    return emitWithReturning(`INSERT INTO ${target} DEFAULT VALUES`, node, ctx);
  }
  const columns = node.columnValues
    .map((cv) => quoteIdent(cv.column))
    .join(", ");
  const values = node.columnValues
    .map((cv) => emitExpression(cv.value, ctx))
    .join(", ");
  return emitWithReturning(
    `INSERT INTO ${target} (${columns}) VALUES (${values})`,
    node,
    ctx,
  );
}
```

`emitWithReturning` appends `RETURNING <emitSelectList(node.returning)>`
when non-null. `emitSelectList` already exists; reuse it.

Parameter numbering: VALUES first (left-to-right), then RETURNING
(in case anyone uses parameter-bearing expressions there later —
not possible today, but the order is canonical).

### Fluent layer

New file `src/query/Insert.ts`:

```ts
export class Insert<
  Columns extends ColumnsShape,
  Returning extends ColumnsShape | null,
> {
  // Phantoms for overload resolution + return-type inference.
  declare readonly _kind: "insert";
  declare readonly _columns: Columns;
  declare readonly _returning: Returning;

  constructor(readonly node: InsertNode) {}

  /** Add or replace the RETURNING clause. */
  returning<const Items extends readonly ProjectableItem[]>(
    ...items: Items
  ): Insert<Columns, ProjectedShape<Items>> {
    const projectionItems = items.map(toProjectionItem);
    return new Insert(
      insertNode({
        target: this.node.target,
        columnValues: this.node.columnValues,
        returning: projectionItems,
      }),
    );
  }
}
```

`toProjectionItem` is the existing helper in `Relation.ts`; lift it
into `src/query/projection.ts` so both `Relation` and `Insert` import
it without circular ref. (Pure refactor; one move, no behaviour change.)

`src/schema-runtime/defineTable.ts` — extend the `Table` type and the
runtime construction:

```ts
export type Table<
  Alias extends string,
  Columns extends ColumnsShape,
> = Relation<Columns> &
  Readonly<{
    _tableName: Alias;
    _schema: string;
  }> & {
    readonly [Name in keyof Columns & string]: Column<
      Alias,
      Name,
      Columns[Name]
    >;
  } & {
    as<NewAlias extends string>(alias: NewAlias): Table<NewAlias, Columns>;
    insert(attrs: InsertableAttrs<Columns>): Insert<Columns, null>;
  };
```

Implementation in `buildTable`: alongside `as`, attach an `insert`
method that walks the supplied `attrs` object, builds an
`InsertColumnValue[]` (each value wrapped as a `Parameter`
ExpressionNode via `parameter(value)` from `ast/expression.ts`),
and constructs a fresh `Insert` with `returning: null`. Iteration
order preserves the user's object key order (per ES2015+).

### Type machinery

`src/query/types.ts` — add `InsertableAttrs<Columns>`:

```ts
type IsRequired<
  Type extends ColumnType<unknown, string, boolean, boolean, boolean>,
> = Type["isGenerated"] extends true
  ? false
  : Type["nullable"] extends true
    ? false
    : Type["hasDefault"] extends true
      ? false
      : true;

type InsertableKeys<Columns extends ColumnsShape, Required extends boolean> = {
  [Name in keyof Columns]: Columns[Name]["isGenerated"] extends true
    ? never
    : IsRequired<Columns[Name]> extends Required
      ? Name
      : never;
}[keyof Columns];

/**
 * The TS shape `.insert(attrs)` accepts. Required keys: NOT NULL,
 * no DEFAULT, not generated. Optional keys: nullable OR has DEFAULT.
 * Generated columns are absent (forbidden).
 */
export type InsertableAttrs<Columns extends ColumnsShape> = Prettify<
  { [Name in InsertableKeys<Columns, true>]: Columns[Name]["_tsType"] } & {
    [Name in InsertableKeys<Columns, false>]?:
      | Columns[Name]["_tsType"]
      | (Columns[Name]["nullable"] extends true ? null : never);
  }
>;
```

`Prettify` already exists (used in `RowOf`); export it from
`types.ts` if it isn't already, or duplicate the local declaration.

### `Database.run` overloads

`src/executor/Database.ts`:

```ts
async run<Columns extends ColumnsShape, Returning extends ColumnsShape>(
  insert: Insert<Columns, Returning>,
  client?: PoolClient,
): Promise<RowOf<Returning>[]>;

async run<Columns extends ColumnsShape>(
  insert: Insert<Columns, null>,
  client?: PoolClient,
): Promise<{ readonly rowCount: number }>;

async run<Columns extends ColumnsShape>(
  query: Relation<Columns> & {
    readonly _columns: { readonly __tenonDuplicateColumns?: never };
  },
  client?: PoolClient,
): Promise<RowOf<Columns>[]>;
```

Implementation: type-narrow on the input — if it's an `Insert`
(check via `instanceof Insert` or `node.kind === "Insert"`), call
`insertToSql`; otherwise `relationToSql`. Return shape branches on
the presence of `RETURNING` in the node:

```ts
if (insertNode.returning === null) {
  return { rowCount: pgResult.rowCount ?? 0 };
}
return pgResult.rows as RowOf<Returning>[];
```

The Insert overloads come **before** the Relation overload so TS
overload resolution prefers them when the argument is an Insert
(both have a `_columns` phantom; Insert additionally has `_kind`).

3. Manual smoke against the test database:

4. Type-error spot checks (must fail to compile):
   - `users.insert({})` — missing required NOT NULL columns.
   - `users.insert({ id: 1, ... })` when `id` is generated/serial —
     `id` not in `InsertableAttrs<UsersColumns>`.

     not on `Relation`.
   - `db.run(users.insert({...}))` consumed as if it returned
     rows — should be `{ rowCount }`.

## Open questions / risks

- **Tooltip readability of `InsertableAttrs<...>`.** The mapped-type
  intersection may render awkwardly in IDE tooltips. `Prettify`
  should flatten it; if not, hand-write the resolved shape via a
  `keyof`-driven conditional.
- **`hasDefault` semantics.** We collapse `atthasdef` and identity
  columns into a single boolean. If a future iteration wants to
  distinguish (e.g. for surfacing the default expression in
  diagnostics), this needs a second flag — additive.
- **Unaliased emit for aliased tables.** `users.as("u").insert(...)`
  emits `INSERT INTO "public"."users"` and drops the alias. Document
  this; users are unlikely to need aliased INSERTs.
- **Five-generic `ColumnType`.** Verbose; cost is mostly visual at
  the type-annotation site. The factory hides it. If it becomes
  painful in a follow-up, consolidate into a `Flags` bag — that's a
  pure refactor with no behaviour change.
- **`Prettify` location.** Currently local in `types.ts`. If
  `InsertableAttrs` re-uses it, lift it to a top-level export to
  avoid duplication.

## Deferred (still post-v1.7)

- **Rails-style `users.where(...).insert(...)` chain.** Sketched
  separately. Requires `.where` on Tables to return an
  `InsertableScope` that retains `.insert`, plus a runtime
  extractor for top-level AND of `column.eq(literal)` predicates.
  Throws on anything else.
- **`insertMany([...])`** — additive on `Insert`/`InsertNode` (the
  AST already takes a column-values list; multi-row VALUES is
  straightforward).
- **`ON CONFLICT (cols) DO NOTHING / DO UPDATE SET ...`** — extend
  `Insert` with `.onConflict(...)`.
- **`UPDATE` and `DELETE`.** Each is its own AST + serialiser path
  - fluent class; same shape as Insert.
- **Transactions / savepoints.** Already deferred from v1.
- **Streaming / cursors.** Already deferred.
