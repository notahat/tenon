# `tenon` — `find` throws by default (v1.14)

## Context

v1.11 added `Table.find(id)` returning a `SingleRow<C>` whose
`db.run(...)` resolves to `RowOf<C> | null`, with an explicit
`.orThrow()` step to opt in to a non-null result. v1.13 has now landed
the full read/write surface around that shape.

Two friction points have surfaced with the `.orThrow()` two-step:

- It puts a runtime concern (does this row have to exist?) into the
  middle of a fluent chain, where its placement is ambiguous —
  before/after a `.where`, before/after a `.delete`/`.update`, etc.
- The common case (Rails-style "fetch by primary key, blow up if
  missing") needs the longer form, while the rarer "tolerate missing"
  case looks the same length.

The decision is to flip the default and remove the opt-in entirely:
`find(id)` throws on miss; there is **no** nullable PK lookup. Users
who want to tolerate a missing row drop down to `.where(...)` and read
the array.

User-confirmed scope decisions:

- **No nullable PK lookup at all.** No `findBy`, no `.orNull()`. If you
  want "row or nothing", write `users.where(users.id.eq(1))` and read
  index 0.
- **`SingleRow` becomes the throwing class.** `SingleRowOrThrow` is
  deleted. `db.run(singleRow)` resolves to `RowOf<C>`, never null.
- **Belongs-to FK accessors throw on missing parent.** A belongs-to
  walk (`post.author`) hits the same `db.run` path as `find` and
  raises `RowNotFoundError` if the JOIN finds nothing — including the
  case where the FK column itself is null. Callers with nullable FKs
  must check the scalar (`post.authorId`) themselves before walking.
  This is a deliberate sharpness choice consistent with dropping the
  nullable variant.

This is a **breaking change**. Every existing call site that did
`find(...).orThrow()` becomes `find(...)`; every site that relied on
`find` returning null on miss must switch to `.where(...)` and handle
an empty array.

## Decisions

- **Reuse `SingleRow` as the new throwing class** rather than renaming
  `SingleRowOrThrow` to `SingleRow`. `SingleRow` is already the user-
  facing name in error messages, doc anchors, the `_kind` phantom, and
  exports; flipping its semantics in place keeps existing references
  pointing at the right concept.
- **Delete `SingleRowOrThrow` entirely** (class, executor branch,
  overload, export, test references). The retained throwing semantics
  collapse into `SingleRow`.
- **Delete `SingleRow.orThrow()`.** No deprecation shim — pre-1.0
  library, single user, and the rename is mechanical.
- **`WritableSingleRow` continues to extend `SingleRow`.** It still
  carries `.delete()` and `.update(attrs)`. Because `instanceof
SingleRow` catches both, the executor needs only one branch.
- **`RowNotFoundError` is retained** with a slightly broader message
  (drop the `.orThrow()` reference). It is the only signal a missing
  row produces now.
- **Belongs-to runtime construction is unchanged.**
  `buildBelongsToSingleRow` already returns `SingleRow<...>`. Once
  `SingleRow` throws, the throwing semantics fall out for free.
- **Has-many accessors are unaffected.** They return
  `Relation<childColumns, FK[]>`, which resolves to an array; "no
  rows" is `[]`, never an error.
- **`LIMIT 1` is preserved.** `Table.find` keeps the existing
  `limitNode(whereNode(node, predicate), 1)` wrap. Throwing on zero
  rows doesn't change "we want at most one"; the existing predicate
  on the PK already guarantees that, and dropping the LIMIT would
  spend a round-trip on a behaviour change we don't need.

## Design

### Class shape (`src/query/SingleRow.ts`)

```ts
/**
 * A query that returns exactly one row when run. `db.run(singleRow)`
 * resolves to `RowOf<Columns>` and rejects with `RowNotFoundError`
 * when the underlying SQL returns zero rows. Built by
 * `Table.find(id)` and by belongs-to accessors merged on by
 * `defineSchema`.
 */
export class SingleRow<Columns extends ColumnsShape> {
  declare readonly _kind: "SingleRow";
  declare readonly _columns: Columns;

  constructor(readonly node: RelationNode) {}
}

export class WritableSingleRow<
  Columns extends ColumnsShape,
> extends SingleRow<Columns> {
  // .delete() and .update(attrs) — unchanged.
}

/** Thrown by `db.run(singleRow)` when the query returns zero rows. */
export class RowNotFoundError extends Error {
  constructor(message = "tenon: no row found for SingleRow query") {
    super(message);
    this.name = "RowNotFoundError";
  }
}
```

Removed: `SingleRowOrThrow` class, `SingleRow.orThrow()` method.

The header comment on the file is rewritten to describe the throwing
contract; the v1.11-era paragraph about `.orThrow()` is dropped.

### Executor (`src/executor/Database.ts`)

Drop the import of `SingleRowOrThrow`. Drop the
`run<C>(statement: SingleRowOrThrow<C>, ...)` overload. Modify the
remaining SingleRow overload:

```ts
run<Columns extends ColumnsShape>(
  statement: SingleRow<Columns>,
  client?: PoolClient,
): Promise<RowOf<Columns>>;
```

Drop the `instanceof SingleRowOrThrow` branch. Modify the
`instanceof SingleRow` branch to throw on miss:

```ts
if (statement instanceof SingleRow) {
  const compiled = relationToSql(statement.node);
  const result = await runner.query(compiled.text, [...compiled.params]);
  const first = result.rows[0];
  if (first === undefined) throw new RowNotFoundError();
  return first;
}
```

`WritableSingleRow extends SingleRow`, so this branch covers both.

### Type-level surface (`src/query/types.ts`)

No structural change. `WiredSingleRow<T, S>` already references
`WritableSingleRow<T["_columns"]>`; `BelongsToAccessors` already
reference `SingleRow<...>`. Both inherit the new throwing semantics
through `db.run`'s overload.

### Schema-runtime hooks

- `src/schema-runtime/defineTable.ts` — `find` runtime construction
  unchanged (`new WritableSingleRow(...)`). Doc comments on
  `FindMethod` are updated to describe throwing semantics.
- `src/schema-runtime/defineSchema.ts` — header / accessor comments
  for `buildBelongsToSingleRow` and the wired-find paragraph are
  updated to describe throwing on missing parent. No code change.

### Public exports (`src/index.ts`)

- Remove the `SingleRowOrThrow` re-export.
- Keep `SingleRow`, `WritableSingleRow`, `RowNotFoundError`.
